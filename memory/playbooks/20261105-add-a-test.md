# 给新功能加测试（标准流程）

- 日期：2026-11-05
- 适用：任何要进 `src` 的新函数 / 模块 / 接口

## 步骤

1. **定子区**：纯逻辑 → `tests/unit`；跨模块 → `tests/integration`；外部 API 格式 → `tests/contract`；CLI → `tests/e2e`。
2. **造夹具**：`tests/fixtures/<kind>/<name>.sample`，脱敏（无账号、无绝对路径、无真实 token）。
3. **写测试**：断言先写失败用例（缺字段、畸形输入、边界值），运行确认红：
   ```powershell
   python -m pytest tests\unit\test_acf.py -q
   ```
4. **写实现**：最小实现让测试变绿；不要一次写完美。
5. **补安全用例**：路径穿越 `..\`、`file://`、超大声明、Lua 注入。
6. **落报告**：
   ```powershell
   pwsh -File tools\scripts\run-tests.ps1 -Area unit
   ```
7. **过门禁**：`pwsh -File tools\scripts\gate-check.ps1 -TaskId <ID>`。
8. **更新 ARD 与 memory**：任务状态、会话记录；有坑写 errors 条目。

## 判定标准

- 红过才写实现（没有失败过的测试等于没写）。
- 报告文件落在 `tests/reports/`。
- ARD 任务状态不再是 `pending`。
