# 2026-11-06 · 别把「窗口有标题、进程活着」当成 L3 通过

## 现象
从独立目录直接跑 `left4dead2.exe`：进程活着、CPU 涨到 190 s、窗口标题是 `Left 4 Dead 2 - Direct3D 9`。
按这些指标我判定 L3 通过 —— **是错的**。截图显示屏幕上是 Engine Error 对话框：
`Steam is not running. You must start Steam in order to play this game.`

## 根因
1. `steam_api` 的所有权/授权校验失败：引擎与 D3D9 设备先起来了，授权阶段才抛错，所以「有窗口、有 CPU」都成立。
2. 我用「进程存活 + 标题关键字」做判据，恰好全是假阳性信号；真正的判据是「是否进入主界面」。
3. 错误对话框是独立窗口，标题变成 `Engine Error`，CPU 曲线随即**冻结**（190.4 s 不再增长）—— 这个特征其实一眼能看出来。

## 处置
- 修正 ARD：M4-V03 → failed（附截图路径），M4-V04 → blocked；写入 D-019（L3/L4 前置条件 = Steam 在跑）。
- 新增 `tools/scripts/play-body.ps1`：默认拒绝自启 Steam（D-016 授权门），`-StartSteam` 才允许；
  自动检测 `Error` 标题并返回退出码 3，避免再次把错误框当成功。
- 判定规则改为三选二：① 标题不含 `Error` ② CPU 持续增长 ③ 截图能看到主界面。

## 复用建议
- 自动化验收时，**永远抓一张截图**：进程指标骗人，像素不骗人。
- 把「失败的可观测特征」写进脚本（这里：标题含 Error、CPU 停滞），让下次判定不依赖人眼。
- 记录证据时要连「误判 → 修正」一起写进 ARD：进度文档的价值在于可信，不在于好看。
