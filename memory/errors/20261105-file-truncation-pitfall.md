# 整文件重写时误用片段写回导致文件被截断

- 日期：2026-11-05
- 类型：错误
- 严重度：P0（脚本静默失效）
- 来源任务：M0-T05

## 现象
用脚本修改 `tools/scripts/desensitize-scan.ps1` 的两行后，文件只剩前 80 行：
末尾的 `exit 1` 丢失，导致扫描命中敏感内容仍返回 **exit 0**，pre-commit 形同虚设。

## 根因
“读取时设了 `limit: 80`，改完把整段 `lines.join("
")` 写回”——读的是片段，写的是全文件，
文件被截断且没有任何报错。

## 处置
1. 补齐缺失尾部（BLOCKED 列表输出 + `exit 1`）。
2. 复测：泄漏文件 → `git commit` 退出码 1，并打印 `[pre-commit] blocked`。
3. 全量重写该脚本，避免二次拼接。

## 防复发
- 修改文件时：**读全量（或按行精确替换）再写**；禁止用受限读取的结果覆盖整文件。
- 涉及安全门禁的脚本，改完必须做“**应该失败**”的负向测试（含 token 的提交必须被拒）。
- 生成脚本类内容时，PowerShell 里的 `${...}` 与反引号会与模板语法冲突：用占位符替换后再落盘。
- 已纳入 `tests/security` 的规划用例：门禁脚本必须可拦截已知泄漏样本。
