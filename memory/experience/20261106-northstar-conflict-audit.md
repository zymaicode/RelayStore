# 2026-11-06 · 按北极星清理冲突约定（全项目排查）

## 现象
宪法写着「唯一验收标准 = 产出本体且稳定运行」，但同一套文档里还有一堆把本体挡在门外的约定：
`D:\Steam` 只读、研究阶段不写库、单文件 256 MB 上限、同域 1s 硬限速、禁止跟随 CDN 重定向。
规则与目标互相打脸，Agent 照着规则做永远到不了 L4。

## 根因
M0 基建期的规则是「研究模式」写的（只看不动），后来北极星升级成「产出可运行本体」（必须动），
但没人回头审一遍规则。**目标升级而约束不升级**，是最隐蔽的一致性债。

## 处置
1. 关键词族扫全项目：只读 / 研究阶段 / 不向 / 上限 / 不分发 / 不做 / 不实现 / 不得 / 禁止 / 限速 / 重试 / 配额。
2. 每条只问一句「它会不会挡住本体落地或运行？」——会，就改成「能做 + 留回滚」；不会（工程卫生、安全），原样不动。
3. 冲突项 6 处：`D:\Steam` 只读（4 个文件）、256 MB/文件硬上限、1 req/s 硬限速、CDN 重定向禁令、PRD 安全行的大小上限、
   memory 里的「不要写 D:\Steam」。
4. 改成「可写但必留回滚」时同步加风险 R-11（误写破坏客户端），并把备份对象写死：`steamapps\*.acf`、`libraryfolders.vdf`。
5. 授权类表述（只做研究 / 自有内容 / 不分发）上一轮已清；本轮只动「操作层」限制。
6. **修正**：`D:\Steam` 的「可写」被用户当场收回 —— 本机客户端与配置是用户主权，改法改为「默认不写 + 授权闸门 + 独立产物目录」（ARD D-016）。

## 复用建议
- 改目标时立刻做一次「冲突扫描」：凡是 `禁止 / 不得 / 上限 / 只读 / 不` 开头的条目都要过一遍。
- 删限制的正确姿势不是清空，而是**换成可回滚的许可**（可写 + 先备份 + 记回滚点），这样规则仍然可执行。
- 单文件大小、并发、限速这类「保护性默认值」要写成默认值 + 可配置，别写成天花板；否则大文件/全量下载当场卡死。
- **本机环境（Steam / 配置 / 注册表）的写权限不属于工程优化范畴**：目标再高也不能默认改用户机器；默认拒绝、独立目录产出、授权后限定范围 + 备份，三件套缺一不可。
