# 2026-11-06 · 项目文档里的「范围限制条款」清理

## 现象
项目宪法与配套文档里散落着同一类表述：「仅用于自有内容、免费内容」「仅限自有授权（本账号已购买）的游戏与免费内容」
「不得产出/分发绕过分发授权的资源包」「范围外：不实现绕过 Steam 授权的下载器」。作者授权后要求删除这一类范围限制。

## 根因
这类条款是在 M0 基建期一次性写入的「保守兜底」，散在 4 个文件 8 处（CLAUDE §1/§1.1/§6/§7.7、AGENT 验收口径、
PRD §1/§4.2/§10、ARD D-007 + Session 04）。之后北极星目标（§1.1 产出可运行本体）与这些限制直接冲突，
但没人回头改，导致「宪法」和「终局」互相打脸 —— 典型的一致性债。

## 处置
1. 先 grep 收敛清单：`自有|合规|授权|盗版|仅限|不得|Out of scope`，跳过 `opensource/`（只读）。
2. 逐条改写而不是整段删掉空着：把限制性表述换成等价的「授权范围由用户界定 + 保留工程/安全约束」句子，
   文档结构不塌，且明确表态「不设范围限制」。
3. ARD 按历史记账：D-007 标「已废止（D-014）」、新增 D-014 决策 + Session 05、版本号 v0.4→v0.5。
   决策日志是历史，不抹除只标废止。
4. 快照（`backup/vcs`、`src/data/tmp/backup-staging`）是生成物：直接镜像这 4 个文件保持一致，
   真正的快照提交留给下一次 `backup-snapshot.ps1`（该脚本会 git commit，未经要求不主动跑）。

## 复用建议
- 改「项目宪法」先列清单再动手：`grep` 出所有同义句，一次改完，避免只改首章漏掉 PRD/ARD。
- 限制条款的删除方式：**换句不删段**。删成空白会让后来者以为漏写，换句能同时表达「已解除」和「还剩什么约束」。
- 生成物（snapshot / staging）不要单独手改后再忘记：要么同步镜像，要么统一由脚本重生成，二选一。
